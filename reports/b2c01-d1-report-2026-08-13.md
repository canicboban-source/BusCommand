## Root cause (actual)

Two stacked client defects in one orchestration function:

1. **Hard bug — CA never runs in prod**  
   `superadminCreateCompanyAdmin` (`js/admin/superadmin.js:1035`) does  
   `document.getElementById("sa-create-admin-btn")`.  
   That ID **does not exist** in `staff.html` (only `#sa-create-company-btn` submit exists).  
   `runSingleSubmission(null, …)` (`js/core/submit-lock.js:4`) returns `{ started: false }` without calling the task → **`ApiClient.createUser` / `POST /api/admin/create-user` never executes**.

2. **UX/orchestration bug — close ignores CA outcome**  
   `superadminSubmitCreateModal` (`:259–270`) always calls `superadminCloseCreateModal()` after company success, even when CA was skipped/failed. Close only hides the modal (fields not cleared), but the SA sees a completed create flow.

3. **Recovery trap**  
   Re-submit after orphan company: `createCompany` → **409** `company-exists` → `superadminCreateCompany` returns false → early `return` **before** CA attempt. So the same modal cannot finish CA for an already-created companyId.

Server side is comparatively sound: SA-only create-company; create-user via `requireUserProvisioner`; company transaction rejects duplicates; Auth+Firestore CA provisioning has compensation on partial Auth failure — but company from step 1 is never rolled back (expected non-atomic cross-system).
